\section{Introduction}

\subsection{Purpose}

\subsubsection{Overview of the Document}
This Software Requirements Specification (SRS) document provides a comprehensive description of the Namal Criko cricket simulation training platform. The document serves as the primary reference for all stakeholders involved in the development, testing, and deployment phases of the project. It establishes a clear understanding of the system's functionalities, constraints, and quality attributes, ensuring alignment between technical teams and the requirement provider.

\subsubsection{Purpose of the SRS}
The purpose of this SRS document is to:
\begin{itemize}
    \item Define all functional and non-functional requirements for the Namal Criko platform in detail
    \item Serve as a baseline for project planning, design, implementation, and validation activities
    \item Provide clear specifications for quality assurance teams to develop comprehensive test cases
    \item Enable future maintenance teams to understand system architecture and design decisions
    \item Document assumptions, dependencies, and constraints that influence system development
\end{itemize}

\subsection{Scope}

\subsubsection{Product Identification}
Namal Criko is a web-based interactive cricket simulation training platform designed specifically for students and cricket enthusiasts at Namal University . The system provides a controlled, technology-driven environment where users can learn and practice various cricket techniques through visual simulations combined with comprehensive textual instruction.

\subsubsection{Product Features}
\paragraph{What Namal Criko Will Do:}
\begin{itemize}
    \item Provide interactive simulations for batting techniques including drives, sweeps, cuts, pulls, and defensive shots
    \item Offer bowling simulations covering fast bowling, spin bowling, and variations (Yorker, bouncer, slower ball)
    \item Deliver step-by-step visual guidance with body movement demonstrations and timing indicators
    \item Enable users to select specific techniques for focused practice sessions
    \item Track individual player performance metrics including matches played, run rate, and skill progression
    \item Implement hybrid learning through combination of interactive simulations and descriptive technical text
    \item Support administrative control over user access, content management, and performance monitoring
    \item Provide a help desk system for user query resolution and technical support
    \item Allow administrators to post cricket-related event announcements and advertisements
\end{itemize}

\paragraph{What Namal Criko Will Not Do (Initial Release):}
\begin{itemize}
    \item Provide real-time multiplayer cricket matches or competitive gameplay
    \item Include artificial intelligence-based opponent players
    \item Support virtual reality (VR) or augmented reality (AR) interfaces
    \item Offer mobile native applications (initial release is web-only)
    \item Integrate with external cricket statistics databases or APIs
    \item Provide live video streaming or recorded video tutorials
    \item Include payment gateways for premium features or subscriptions
    \item Support multiple languages (English only in initial release)
\end{itemize}

\subsubsection{Application of the Software}
Namal Criko addresses critical gaps in cricket training by providing:
\begin{itemize}
    \item \textbf{Accessible Training:} Eliminates geographical and temporal constraints by providing 24/7 access to cricket training simulations
    \item \textbf{Cost-Effective Learning:} Reduces dependency on expensive coaching sessions and physical training facilities
    \item \textbf{Technique Mastery:} Enables focused practice on specific techniques with immediate visual feedback
    \item \textbf{Performance Tracking:} Provides data-driven insights into skill progression and areas requiring improvement
    \item \textbf{Safe Practice Environment:} Allows beginners to learn fundamental techniques without risk of injury
    \item \textbf{Supplementary Training Tool:} Complements physical practice by reinforcing theoretical understanding
\end{itemize}

\subsubsection{Goals and Benefits}
\begin{itemize}
    \item \textbf{Skill Development:} Accelerate the learning curve for cricket techniques through interactive practice
    \item \textbf{Accessibility:} Provide cricket training resources to students who lack access to professional coaching
    \item \textbf{Engagement:} Increase student interest in cricket through gamified learning experiences
    \item \textbf{Data Analytics:} Enable coaches and administrators to monitor student progress systematically
    \item \textbf{Community Building:} Foster a cricket culture within Namal University through shared learning platform
    \item \textbf{Scalability:} Build foundation for future enhancements including multiplayer modes and advanced analytics
\end{itemize}

Namal Criko is an independent web-based cricket training platform designed to supplement traditional physical training methods. Unlike commercial cricket games focused on entertainment, Namal Criko focous educational content and technique mastery through interactive simulations paired with instructional materials.

Namal Criko serves as a complementary tool to physical cricket practice rather than a replacement. It provides:

\subsection{Product Functions}
The core functions of Namal Criko are organized into three major functional areas:

\subsubsection{Cricket Technique Simulations}
\paragraph{Batting Simulations}
The system provides comprehensive batting technique simulations organized by shot type:

\begin{itemize}
    \item \textbf{Defensive Techniques}
    \begin{itemize}
        \item Forward Defense: Body position, bat angle, weight transfer
        \item Backward Defense: Footwork, bat-pad gap, balance maintenance
        \item Leaving Deliveries: Judgment, shoulder drops, bat withdrawal
    \end{itemize}
    
    \item \textbf{Attacking Shots}
    \begin{itemize}
        \item Straight Drive: Timing, follow-through, elbow position
        \item Cover Drive: Footwork, bat path, weight transfer
        \item Square Drive: Bat angle, foot placement, shot control
        \item Pull Shot: Weight distribution, head position, shot timing
        \item Hook Shot: Technique variation, risk management, shot selection
        \item Cut Shot: Backward movement, bat angle, wrist work
        \item Sweep Shot: Positioning, bat angle, shot execution
        \item Reverse Sweep: Grip change, body position, shot control
    \end{itemize}
\end{itemize}

Each simulation includes:
\begin{itemize}
    \item Frame-by-frame breakdown of body movements
    \item Timing indicators for optimal shot execution
    \item Common mistakes and correction tips
    \item Variation demonstrations (e.g., different ball speeds, lengths)
\end{itemize}

\paragraph{Bowling Simulations}
The system covers major bowling categories with technique-specific guidance:

\begin{itemize}
    \item \textbf{Fast Bowling}
    \begin{itemize}
        \item Run-up mechanics: Rhythm, acceleration, approach angle
        \item Delivery stride: Front foot placement, back foot drive, balance
        \item Arm action: Bowling arm path, release point, follow-through
        \item Variations: Yorker, bouncer, slower ball, knuckle ball
    \end{itemize}
    
    \item \textbf{Spin Bowling}
    \begin{itemize}
        \item Off-Spin: Finger position, wrist action, loop trajectory
        \item Leg-Spin: Wrist position, ball release, turn generation
        \item Arm Ball: Grip variation, release modification
        \item Doosra/Googly: Advanced technique demonstrations
    \end{itemize}
    
    \item \textbf{Medium-Pace Bowling}
    \begin{itemize}
        \item Swing bowling: Wrist position, seam orientation, release point
        \item Cutters: Grip variation, finger work, seam manipulation
        \item Change of pace: Rhythm variation, deception techniques
    \end{itemize}
\end{itemize}

    \begin{enumerate}

        \item User fills mandatory fields with validation checks

        \item System sends confirmation email to user

    \begin{itemize}
        \item Email must be unique in system
        \item Password minimum 8 characters with alphanumeric combination
        \item Contact number must be valid format
        \item All fields mandatory
    \end{itemize}

\paragraph{FR-002: Admin Account Approval}
\begin{itemize}
    \item \textbf{Description:} The system shall require administrator to manually approve new user accounts before granting access
    \item \textbf{Inputs:} Admin credentials, user account selection, approval/rejection decision
    \item \textbf{Process:}
    \begin{enumerate}
        \item Admin logs into admin portal
        \item Admin views list of pending account approvals
        \item Admin reviews user information
        \item Admin approves or rejects account
        \item System updates account status
        \item System sends status notification email to user
    \end{enumerate}

\paragraph{FR-003: User Login (Player)}

\end{itemize}

\subsection{Performance Requirements}

\paragraph{NFR-001: Response Time}
\begin{itemize}
    \item Page load time shall not exceed 3 seconds on standard broadband (5 Mbps)
    \item Simulation playback shall start within 2 seconds of user clicking "Play"
    \item Database queries shall return results within 1 second for 95\% of requests
    \item Search functionality shall display results within 2 seconds
\end{itemize}

\paragraph{NFR-002: Concurrent Users}
\begin{itemize}
    \item System shall support minimum 500 concurrent users without significant degradation
    \item System shall scale to handle 1000 concurrent users with optimized performance
    \item Database shall handle 100 simultaneous read/write operations
\end{itemize}

\paragraph{NFR-003: Throughput}
\begin{itemize}
    \item Web server shall handle 50 requests per second during peak usage
    \item Static assets (images, CSS, JS) shall be delivered efficiently via caching
    \item API endpoints shall process 30 requests per second for dynamic content
\end{itemize}

\paragraph{NFR-004: Resource Utilization}
\begin{itemize}
    \item Server CPU usage shall not exceed 80\% under normal load
    \item Memory usage shall remain below 70\% of allocated capacity
    \item Database storage shall be optimized with indexing for frequently queried fields
\end{itemize}

\subsection{Safety Requirements}

\paragraph{NFR-005: Data Safety}
\begin{itemize}
    \item System shall implement regular automated database backups (daily incremental, weekly full)
    \item Backup retention period shall be minimum 30 days
    \item Disaster recovery plan shall ensure system restoration within 24 hours
\end{itemize}

\paragraph{NFR-006: User Data Protection}
\begin{itemize}
    \item Personal user information (passwords) shall be encrypted using industry-standard hashing algorithms (bcrypt)
    \item Passwords shall never be stored in plain text or logged
    \item Password reset tokens shall be single-use and expire after 1 hour
\end{itemize}

\subsection{Security Requirements}

\paragraph{NFR-007: Authentication Security}
\begin{itemize}
    \item All authentication attempts shall be logged for security audit
    \item Accounts shall be locked after 5 consecutive failed login attempts
    \item Session tokens shall be invalidated after 120 minutes of inactivity
    \item Re-authentication required for sensitive operations (password change, email update)
\end{itemize}

\paragraph{NFR-008: Authorization Controls}
\begin{itemize}
    \item Role-based access control (RBAC) shall enforce separation between player and admin functions
    \item Admin actions shall require elevated privilege verification
    \item Users shall only access their own data unless specifically authorized
    \item API endpoints shall validate user permissions for each request
\end{itemize}

\paragraph{NFR-009: Data Transmission Security}
\begin{itemize}
    \item All client-server communication shall use HTTPS (TLS 1.2 or higher)
    \item Secure headers (HSTS, CSP) shall be implemented to prevent common web vulnerabilities
    \item Cookies shall be marked as secure and HTTP-only where applicable
\end{itemize}

\paragraph{NFR-010: Input Validation}
\begin{itemize}
    \item All user inputs shall be validated both client-side and server-side
    \item SQL injection prevention through parameterized queries or ORM
    \item Cross-site scripting (XSS) protection through output encoding
    \item File uploads shall be scanned for malware and restricted to approved formats
\end{itemize}

\subsection{Software Quality Attributes}

\paragraph{NFR-011: Reliability}
\begin{itemize}
    \item System shall maintain 99\% uptime during academic periods
    \item Mean Time Between Failures (MTBF) shall exceed 720 hours (30 days)
    \item Mean Time To Repair (MTTR) shall be less than 4 hours for critical failures
    \item Error rate shall not exceed 1\% of all user interactions
\end{itemize}

\paragraph{NFR-012: Availability}
\begin{itemize}
    \item System shall be available 24/7 with scheduled maintenance windows announced in advance
    \item Scheduled maintenance shall not exceed 4 hours per month
    \item High-availability architecture with redundant components where feasible
    \item Graceful degradation when dependent services (email) are unavailable
\end{itemize}

\paragraph{NFR-013: Maintainability}
\begin{itemize}
    \item Codebase shall follow consistent coding standards and documentation
    \item Modular architecture shall allow independent updates to components
    \item Configuration shall be externalized for easy environment-specific adjustments
    \item Comprehensive logging shall facilitate debugging and issue resolution
\end{itemize}

\paragraph{NFR-014: Scalability}
\begin{itemize}
    \item Architecture shall support horizontal scaling for increased user load
    \item Database design shall accommodate growth to 10,000 users
    \item Simulation content shall scale to 500+ techniques without performance degradation
    \item Stateless design shall allow load distribution across multiple servers
\end{itemize}

\paragraph{NFR-015: Usability}
\begin{itemize}
    \item System shall achieve 85\% satisfaction rating in user acceptance testing
    \item New users shall be able to complete first simulation within 5 minutes of registration
    \item Interface shall comply with Web Content Accessibility Guidelines (WCAG) 2.1 Level AA
    \item Help documentation shall be context-sensitive and easily accessible
\end{itemize}

\paragraph{NFR-016: Portability}
\begin{itemize}
    \item Web application shall function correctly across Chrome, Firefox, Safari, and Edge browsers
    \item Responsive design shall provide optimal experience on desktop, tablet, and mobile devices
    \item Application shall be deployable on major cloud platforms (AWS, Azure, GCP)
    \item Database migration shall be scripted and reversible
\end{itemize}

\subsection{Operational Requirements}

\paragraph{NFR-017: Deployment Requirements}
\begin{itemize}
    \item System shall support automated deployment using CI/CD pipelines
    \item Database migrations shall be version-controlled and executable without downtime
    \item Rollback procedure shall be documented and tested for failed deployments
    \item Environment configuration shall be separate from application code
\end{itemize}

\paragraph{NFR-018: Monitoring Requirements}
\begin{itemize}
    \item System shall log all errors and critical events for monitoring
    \item Performance metrics (response time, error rates, user counts) shall be collected
    \item Alerts shall be configured for system failures or performance degradation
    \item Admin dashboard shall display key system health indicators
\end{itemize}

\paragraph{NFR-019: Backup Requirements}
\begin{itemize}
    \item Full system backup shall be performed weekly
    \item Incremental backups shall be performed daily
    \item Backup restoration procedure shall be tested quarterly
    \item Backups shall be stored securely with encryption
\end{itemize}

\paragraph{NFR-020: Compliance Requirements}
\begin{itemize}
    \item System shall comply with Namal University IT policies
    \item Data handling shall follow university privacy guidelines
    \item All third-party components shall be properly licensed for educational use
    \item Security audit shall be conducted before production deployment
\end{itemize}
