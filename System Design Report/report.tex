% ==================== 1. INTRODUCTION ====================
\section{Introduction}

Namal Criko is a web-based cricket simulation training platform designed for Namal University students. The system provides interactive simulations of cricket techniques (batting and bowling) enabling students to learn and practice in a virtual environment.

This Design Report translates the approved Software Requirements Specification (SRS) into a complete system design including behavioral diagrams, structural diagrams, system architecture, prototypes, and traceability documentation.

% ==================== 2. DESIGN ASSUMPTIONS & CONSTRAINTS ====================
\section{Design Assumptions and Constraints}

\subsection{Design Assumptions}

\begin{enumerate}[itemsep=0.3em]
    \item Users have basic web browsing skills and cricket knowledge
    \item Admin approval occurs within 24-48 hours
    \item Users provide accurate registration information
    \item University network provides adequate bandwidth
    \item Administrative staff available for user approval
    \item Cricket experts validate technique accuracy
    \item University continues post-development support
\end{enumerate}

\subsection{Design Constraints}

\textbf{Technology:} Limited to open-source frameworks \\
\textbf{Budget:} Zero-budget project \\
\textbf{Team:} Three members with limited experience \\
\textbf{Timeline:} One academic year \\
\textbf{Hosting:} Free-tier cloud services \\
\textbf{Hardware:} Must work on student devices \\
\textbf{Software:} No proprietary integrations \\
\textbf{Operational:} Limited post-semester maintenance

% ==================== 3. KEY DESIGN DECISIONS ====================
\section{Key Design Decisions}

\subsection{DFD Decomposition}

\textbf{Level 0:} System boundary with external entities (Player, Admin, Email Service) \\
\textbf{Level 1:} Six major processes (User registration and login, Admin Controller, Simulation Manager, Help and ticket manager, Notification and Event Manager, Report and analysis) \\
\textbf{Level 2:} Detailed decomposition of complex processes

\textbf{Justification:} Follows functional logic; single responsibility per process

\subsection{Class Relationships}

\textbf{Inheritance:} \textit{Player} and \textit{Coach} extend the base \textit{User} class to share authentication and profile attributes while maintaining specific roles. \\

\textbf{Association:} \textit{Player} has a one-to-many relationship with \textit{TrainingSession}; a player can perform multiple drills over time. \\

\textbf{Composition:} \textit{Simulation} consists of \textit{Frames} (e.g., Stance, Impact, Follow-through). If a simulation is deleted, these specific 3D frames are also destroyed. \\

\textbf{Aggregation:} \textit{CoachingManual} aggregates \textit{TechniqueGuides}. The guides exist independently of the manual and can be updated or reorganized.

\subsection{Justification for Class Relationships}

\begin{itemize}
    \item \textbf{Inheritance} was chosen to simplify the User Management module, ensuring that both Coaches and Players follow the same security protocols while having different dashboard access.
    \item \textbf{Composition} for the Simulation class ensures data integrity; since a "Frame" (like the Forward Defense stance) has no meaning outside the context of a training session, it is strictly bound to its parent object.
    \item \textbf{Separation of Concerns:} By decoupling the \textit{AIAnalysisEngine} from the \textit{UIController}, we ensure the 3D simulation remains performant even during heavy data processing.
\end{itemize}

\subsection{System Architecture}

\textbf{Architecture:} Three-tier (Presentation-Application-Data)

\begin{itemize}
    \item \textbf{Presentation (Frontend):} Developed using modern web technologies to render the 3D Cricket Simulation and the "Coaching Manual" dashboard.
    \item \textbf{Application (Logic):} This layer processes simulations frames to present techniques like the "Forward Defense" as per ideal standards.
    \item \textbf{Data (Storage):} A secure database layer that manages player profiles, training history, and the library of high-fidelity "Ideal Technique" reference frames.
\end{itemize}

\textbf{UI:} Desktop Familiar design
